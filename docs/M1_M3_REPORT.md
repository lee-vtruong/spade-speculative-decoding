# SPADE M1–M3 implementation status

This report distinguishes implemented code, local automated checks, and server results reported by the user. Dataset and model files in `ERRORFlow` and `training-free-fact-verification` are treated as shared read-only inputs. Outputs belong under this repository's `outputs/`.

## M1 — Benchmark construction

Implemented deterministic AVeriTeC JSON/JSONL loading, stable claim IDs when source IDs are absent, oracle QA and retrieved-evidence benchmark construction, prompt and evidence IDs, SHA-256 manifests, optional tokenizer prompt-length statistics, and classification/citation evaluation. The knowledge-store adapter reads per-claim JSONL files without changing them and only accepts exact `type=claim` query matches. It excludes gold, question, answer, GPT-generated, provenance, and other query types to avoid accidental label or rationale leakage.

User-reported server checks: train/dev files loaded as 3,068/500 claims; 3-example oracle-QA build emitted evidence counts 7, 2, and 1; sampled gold justifications were absent from prompts; target/draft tokenizers had matching vocabulary and special token IDs. The train store's other query types were not fully audited and are not included by this adapter. The dev knowledge store has not been installed in the SPADE workspace.

## M2 — Decoding baselines

Implemented B0 greedy, B0-S sampling, B1 greedy speculative decoding, B2 exact speculative sampling, processing for temperature/top-k/top-p, residual correction, EOS/output length handling, and trace emission. The Hugging Face adapter currently recomputes full prefixes and has no KV-cache rollback. This makes it a correctness/instrumentation adapter; timings and speedups are explicitly non-authoritative.

User-reported server results: B0/B1 greedy token IDs matched on 3 claims × 64 tokens after sequential target-prefix verification. A B2 run committed 64 tokens and exercised 13 rejection rounds with 48 accepted proposal tokens, 13 residual replacements, and 3 extra target tokens. This exercises the correction path but does not establish distributional equivalence. CPU tests cover finite-distribution identities and sampling behavior; GPU sampling calibration across independent seeds remains required.

## M3 — Rejection analysis

Implemented round/token JSONL traces and aggregation for observed acceptance by category, rejection positions, accepted tokens per round, context length, p/q and total-variation diagnostics, timing components, matched-policy diagnostic speedups, and example token traces. `analyze_traces.py` exports JSON, CSV, and plots from real run directories; `evaluate_outputs.py` reports parse, citation-ID, and verdict metrics. Factuality/grounding is explicitly reported as `not_evaluated`; lexical overlap is not semantic evidence.

## Current execution state

The local CPU suite passes 23 tests. The supplied server runs validate smoke-level behavior only. Full-scale benchmark outputs and M3 reports must be generated by following `SERVER_RUNBOOK.md` on `hvtham-server` and retaining the resulting manifests, run configs, and environment records.
